# Architectural Decision Records (ADR)

This log records long-term structural decisions, trade-offs, and design choices. Agents must consult this log to ensure they do not reverse deliberate choices.

## [ADR-001] Ghostty Belongs to the Homebrew Cask Layer
- **Context:** Ghostty can be compiled or packaged via Nix experimental derivations, but its macOS integration requires strict application sandboxing and access to native rendering hooks.
- **Decision:** Ghostty is managed via the Homebrew Casks layer. Since the de-opinionated refactor the framework core declares no casks at all, so the declaration lives in the gitignored `.local/` layer (`casks = [ "ghostty" ]` in `settings.nix`, written by `install.sh`) rather than in `hosts/default.nix`. `nix/home/home.nix` still links its config file, gated on `dotfiles.home.ghostty.enable`.
- **Consequence:** Do not attempt to refactor Ghostty into a standard `nixpkgs` entry. Do not "restore" a core cask declaration for it — the core ships no casks by design.

## [ADR-002] Deprecated `vim.loop` Avoidance
- **Context:** Neovim 0.10+ deprecated the `vim.loop` API namespace in favor of the unified `vim.uv` module layer.
- **Decision:** All Lua config segments (`config/nvim/`) must leverage `vim.uv`. Legacy calls must integrate a fallback interlock check: `(vim.uv or vim.loop)`.
- **Consequence:** Any script rewrite introducing raw `vim.loop.` syntax will fail pre-commit hooks.

## [ADR-003] Downstream Flake Dynamic Syncing
- **Context:** Private infrastructure identifiers cannot leak to public remotes. The local `git+file://` architecture binds them, but ignores uncommitted files.
- **Decision:** A custom `PostToolUse` command hook automatically stages working adjustments. *(Amended by ADR-008: it stages only — the auto-commit was removed.)*
- **Consequence:** Rebuilds evaluate against the working tree including staged changes; untracked files remain invisible, so new files must be `git add`ed (rule R2). Do not remove the auto-stage hook.

## [ADR-004] Impure `.local/` Settings Layer (Sanctioned `builtins.getEnv` Exception)
- **Context:** The gitignored `.local/` layer (machine identity + app selections) is invisible to pure `git+file:` evaluation (untracked files are excluded from the store copy). Empirical sandbox tests showed the `path:` scheme is unsafe: it copies `.git/` into the store, hard-fails on the `core.fsmonitor` daemon socket, and still resolves out-of-tree `.local -> ~/dotfiles-private` symlinks to MISSING under pure evaluation.
- **Decision:** `lib/local.nix` is the single sanctioned impure read point. It resolves `$DOTFILES_LOCAL` → `~/dotfiles/.local` via absolute paths (`/. + "$DIR"`), and `scripts/bin/rebuild` passes `--impure` plus `sudo env DOTFILES_LOCAL=... HOME=...` (sudo may rewrite `$HOME`). Under pure evaluation the loader degrades to empty settings so CI and cold clones evaluate green. *(ADR-007 removed `~/dotfiles-private` from the candidate list; use the `.local -> ~/dotfiles-private` symlink instead.)*
- **Consequence:** Do not add `builtins.getEnv` anywhere else (`validate` enforces this with a `lib/local.nix` exemption). Do not "simplify" the loader to relative paths or the `path:` scheme — both silently break. `.local/hosts/` is reserved for the private flake and must never be auto-imported by the loader (double-import conflicts).

## [ADR-005] Freeze on `global_rules.md` Expansion
- **Context:** `config/windsurf/global_rules.md` carries `trigger: always_on`, so its full contents are injected into every session regardless of task. It had grown to ~109 lines of five-phase enterprise governance — lifecycle classification, compliance matrices, a11y and SLA budgets — most of it irrelevant to any given change in this repo. Stacked on top of `AGENTS.md` and `docs/AI_WORKFLOW.md`, which restate much of the same protocol, the always-on preamble consumed a large share of the context window before the agent had read a single line of the actual diff, degrading attention on the work itself.
- **Decision:** Freeze `global_rules.md` at its current scope. New agent guidance goes into task-scoped locations instead: `docs/` for rationale and architecture, `.devin/skills/` for procedures invoked on demand, and root `CLAUDE.md` (hard cap: under 100 lines) for the always-loaded minimum. Adding a new section to `global_rules.md` requires a superseding ADR that justifies why the guidance must be always-on.
- **Consequence:** `CLAUDE.md` states what the repo is, how to validate, and the load-bearing agent rules, then points outward — progressive disclosure rather than inlining. Agents needing depth must read the linked document. Do not "helpfully" re-expand `global_rules.md` or copy `AGENTS.md` back into `CLAUDE.md`; that regrowth is exactly what this ADR exists to stop.

## [ADR-006] Auto-Commit Is Not a Safety Boundary in a Public Repo (supersedes part of ADR-003)
- **Context:** ADR-003 established a `PostToolUse` auto-commit hook (`config/devin/hooks.json`) that stages `AGENTS.md docs/ config/ nix/ hosts/ scripts/ lib/` and commits to `main` after every `exec` tool call, so that `git+file:` evaluation sees committed state. That decision was made when this repository was private. It is now public, and git history is permanent: anything the hook commits is published without human review. The 2026-07-25 public-purity audit found the compensating control was not merely weak but **absent** — `.gitleaks.toml` declared a `title` and an `[allowlist]` but no rules and no `[extend]` stanza, so gitleaks loaded an empty ruleset. A canary file containing a live-format AWS key, GitHub PAT and Slack token scanned completely clean through both `dot secrets` and the "mandatory, fail-closed" pre-commit hook. The hook could not fail. A blanket allowlist on the whole of `README.md` compounded it.
- **Decision:** Retain the auto-commit mechanism (ADR-003's evaluation constraint is real and unchanged), but stop treating it as reviewed output, and restore the control it depends on:
  1. `.gitleaks.toml` MUST carry `[extend] useDefault = true`. This is now the single most load-bearing line in the repository's secret hygiene; a config without it silently disables all scanning while still reporting success.
  2. Allowlist entries MUST be path-specific. No whole-file entries for documents that accept prose and code samples.
  3. Auto-commits are `wip:` checkpoints, not reviewed history. Squash or rewrite them before pushing to a public remote; never treat "the hook committed it" as evidence that content was vetted.
- **Consequence:** ADR-003 remains in force for the mechanism and must not be decoupled, but its implicit claim that pre-commit scanning makes auto-commit safe is withdrawn. Any future change to `.gitleaks.toml` must be validated against a canary containing known-format secrets — a passing scan proves nothing on its own, because the failure mode is a *clean* result. Treat "no leaks found" as meaningful only after confirming rules are actually loaded.

## [ADR-007] Presence of a `.local/` Directory Is Not Consent
- **Context:** `lib/local.nix` resolved the settings layer by taking the first *existing* directory from `$DOTFILES_LOCAL` → `~/dotfiles/.local` → `~/dotfiles-private`, and set `exists = dir != null`. Three modules then treated that flag as an opt-in signal: `nix/modules/homebrew.nix` defaulted `cleanup` to `"uninstall"`, `nix/modules/system.nix` applied the macOS defaults profile, and `nix/home/home.nix` enabled the full example home profile. But `scripts/bin/setup-private-host` creates `~/dotfiles-private` containing only `flake.nix`, `flake.lock` and `hosts/` — no settings files at all. A user who followed `docs/PRIVATE_HOST_SETUP.md` and never created a `.local/` therefore got `exists = true` from an empty directory while `dotfilesLocal.casks` resolved to `[]`. The first `dot rebuild` would run Homebrew cleanup in `"uninstall"` mode against an empty declared set — **uninstalling every cask on the machine**. `scripts/bin/rebuild` reinforced this by falling back to `DOTFILES_LOCAL=$PRIVATE_FLAKE_ROOT`, and the protective warning in `homebrew.nix` was gated on `!exists`, so it could never fire. The module's own header correctly described this exact hazard; only the predicate was wrong.
- **Decision:** Directory presence is never consent.
  1. `~/dotfiles-private` is no longer a resolution candidate. The supported way to back `.local/` with the private repo is the symlink `install.sh` creates (`.local -> ~/dotfiles-private`), which resolves through the `~/dotfiles/.local` candidate.
  2. A directory counts as a settings layer only if it carries at least one recognized settings file (`settingsFiles` in `lib/local.nix`; mirrored by `has_settings_layer()` in `scripts/bin/rebuild` — keep the two in sync).
  3. `exists` gates nothing behavioural. Modules read explicit tri-state accessors (`homebrewCleanup`, `macosDefaults`, `homeProfile`) where `null` means "unspecified" and the module supplies a non-destructive default.
  4. `homebrew.cleanup` defaults to `"none"` unconditionally, and an assertion refuses to evaluate `"uninstall"`/`"zap"` against an empty cask list.
- **Consequence:** Pruning, macOS defaults and the example home profile are now explicit opt-ins written into `.local/settings.nix`. Existing machines that relied on the implicit defaults must add `homebrew.cleanup`, `system.macosDefaults.enable` and `home.exampleProfile.enable` to keep their current behaviour. The `cold-is-nondestructive` flake check pins the contract: never add a default that a fresh fork would experience as destructive or opinionated.

## [ADR-008] `AGENTS.md` Is the Canonical Agent Contract (supersedes ADR-005)
- **Context:** ADR-005 correctly diagnosed always-on context bloat, but its remedy was vendor-forked: it named `.devin/skills/` and root `CLAUDE.md` as the two destinations for guidance. The result was the duplication it set out to stop. A 2026-07-25 audit found the three-strike loop rule stated in four places — `config/windsurf/global_rules.md`, `.devin/rules/plan-and-execute-guardrail.md`, `.devin/skills/loop-preventer/SKILL.md` (all "3") and `docs/AI_WORKFLOW.md` ("2 consecutive times") — a direct contradiction in files that can all load at once. "Blueprint first" appeared three times, strict rollback twice, stage-before-eval three times, the `getEnv` exception five times. Meanwhile the *operational* contract was trapped in vendor files: "always run `dot validate`" and "never modify `.local/`" existed only in `CLAUDE.md`, and `AGENTS.md` never mentioned the `dot` CLI at all — so an agent arriving with no vendor folder could not learn how to validate its own work. `scripts/bin/validate` compounded this by hard-failing on untracked files under `.devin/` specifically, enforcing one vendor's hygiene as a repo-wide rule.
- **Decision:** `AGENTS.md` is the single canonical, vendor-neutral agent contract: repo layout, the `dot` CLI, numbered hard rules **R1–R8**, workflow, and definition of done. Every vendor file becomes a thin pointer that restates nothing — `CLAUDE.md` (via `@AGENTS.md` import), `.devin/rules/`, `.cursor/rules/agents.mdc`, `.github/copilot-instructions.md`, and `config/windsurf/global_rules.md`, which reverts to genuinely machine-global content only. Rules are cited by number (`R4`), never re-prosed. The three-strike threshold is **3**, stated once in R8. `docs/AI_WORKFLOW.md` is absorbed into `AGENTS.md` §4. `validate`'s agent-config check iterates a vendor-neutral `AGENT_DIRS` list, checking only directories that exist.
- **Consequence:** Adding a new AI tool costs ~5 lines pointing at `AGENTS.md`, and no rule can drift between vendors because no rule is stated twice. ADR-005's under-100-line always-on cap survives, reassigned to `AGENTS.md`. Do not copy rules back into any vendor file, and do not add repo-specific guidance to `global_rules.md` — it is injected into *every* workspace on the machine, not just this one. The auto-commit hook (ADR-003) is likewise reduced to auto-*stage*: `git add` is what makes `git+file:` evaluation correct, while the commit only published unreviewed content to permanent public history.

## [ADR-009] The Live System Builds Only From Published Revisions (amends ADR-003)
- **Context:** The private flake consumed this repo as `git+file:///Users/<me>/dotfiles`, which by itself is safe — the lock pinned a clean `rev` with `ref: refs/heads/main` and no `dirtyRev`. The leak was `scripts/bin/rebuild:63-80`: every `dot rebuild` compared `git -C ~/dotfiles rev-parse HEAD` against `.nodes.dotfiles.locked.rev` and, on any difference, ran `nix flake update dotfiles` inside the private flake. `HEAD` is whatever branch happens to be checked out, so a half-finished experimental branch silently became the live macOS system on the next rebuild, with no prompt and no record. Because the private flake's other four inputs all `follows` `dotfiles/*`, the same auto-bump also repinned `nixpkgs`, `nix-darwin`, `home-manager` and `nix-homebrew`. The failure was latent at the time of writing: `~/dotfiles` sat on a feature branch one commit ahead of the pin, so the next plain rebuild would have relocked the machine onto it. `docs/OPERATIONS.md` documented the auto-relock as a *feature*.
- **Decision:** The live system builds only from revisions that exist somewhere other than this laptop.
  1. The private flake's `dotfiles` input is a published ref (`github:OWNER/REPO`), pinned in `flake.lock`. `scripts/bin/setup-private-host` derives the owner from the user's own `origin` remote — never hardcoded, since this framework is forked — and falls back to `git+file://` only when no GitHub remote exists, printing why.
  2. `rebuild` never mutates the pin. The staleness check is advisory, compares against `origin/main` rather than `HEAD`, prints the manual bump command, and never alters the exit status: a deliberately old pin is a valid state, not an error.
  3. `dot rebuild --override-local[=PATH]` is the sole escape hatch. It passes `--override-input dotfiles git+file://<abs>` plus `--no-write-lock-file`, so a one-off test cannot become the new pin. The `git+file://` prefix is mandatory — a bare path selects the `path:` scheme that ADR-004 established is unsafe here.
  4. `rebuild` gained argument parsing and rejects unknown flags. It previously accepted none, so `dot rebuild --override-local` was silently ignored — the worst outcome for a flag that decides which tree goes live.
- **Consequence:** Promotion is now explicit and three steps: push, `nix flake update dotfiles` in the private flake, commit the lock. `dot update` says so, because the lock it updates no longer drives the machine on its own. ADR-003's mechanism is amended, not withdrawn — `git+file:` staging semantics (R2) still govern `--override-local` builds and `nix flake check` inside this repo, so `git add` remains mandatory before evaluating; only the default rebuild path no longer reads the working tree. ADR-004 is untouched: `--impure` plus `sudo env DOTFILES_LOCAL=... HOME=...` is still exactly how `.local/` is read, and `.local/` remains a machine-local layer that is never published. Note for future work: the `validate` guard at :191 that greps `scripts/bin/rebuild` for a hardcoded hostname is already inert, because it matches a literal `darwin-rebuild` on a line that now builds the command through `"${REBUILD_CMD[@]}"`; `tests/test_rebuild.bats` covers that contract instead.

## [ADR-010] The Adopter Owns the Pin, and the Private Flake Is Host-Plural (extends ADR-009)
- **Context:** ADR-009 made the live system build only from a published revision, and `setup-private-host` derives that revision's repository from the user's own `origin` remote rather than hardcoding one. That is right for a fork and wrong for the far more common first contact: clone `ucod3/dotfiles`, run `install.sh`, and `origin` *is* upstream — so the generated private flake pinned the adopter's Mac to the author's repository. Nothing warned. The adopter could edit their checkout forever and `dot rebuild` would keep building someone else's `main`, and `dot promote` could never work because they cannot push to it. A second, quieter failure sat alongside it: the generated `flake.nix` hardcoded exactly one `darwinConfigurations."<hostname>"`. Cloning the private repo onto a second Mac and re-running `setup-private-host` wrote `hosts/<name>.nix` and then printed a block of Nix for the operator to paste into their own flake by hand — a manual editing step in the middle of what is supposed to be an automated first run, on the machine least likely to have a working editor set up yet. The generated host file also read `users.${user} = import inputs.dotfiles.darwinModules.homeEnvironment;` — a single module, not a list — so every `dot adopt` ended with a warning that nothing imported `home.nix` and another hand edit before the adoption would deploy.
- **Decision:** Ownership and plurality are properties of the generated flake, not of the operator's diligence.
  1. `setup-private-host` compares the derived slug against the upstream it was published from. On a match it explains what pinning upstream means and prompts for the adopter's fork; `--fork OWNER/REPO` and `$DOTFILES_FORK` skip the prompt, and a non-TTY run (bootstrap, CI) proceeds with a loud warning rather than blocking. An explicit `--fork` is never second-guessed, and a fork's own `origin` is pinned silently — the guard fires only on the one case that is actually wrong. `install.sh` asks the same question before cloning, via `--repo` / `$DOTFILES_REPO_URL`.
  2. The generated `flake.nix` builds `darwinConfigurations` from `builtins.readDir ./hosts`. Adding a Mac is dropping in `hosts/<hostname>.nix`; there is nothing to edit. `setup-private-host` detects this layout, writes the host file, stages it (R2 — `git+file:` evaluation excludes untracked files, so an unstaged host file is invisible to the rebuild meant to consume it) and exits. The paste-a-block path survives only for a pre-existing hand-written flake with no `readDir`.
  3. The generated host file uses `users.${user}.imports = [ ... ../home.nix ]`, and `setup-private-host` creates `home.nix` up front — empty but valid, carrying the `dot-adopt` sentinel. The stub and the sentinel live in `lib/private-flake.sh`, shared with `dot-adopt`, because two copies of that heredoc is how they came to disagree in the first place.
- **Consequence:** A fresh clone can no longer quietly pin someone else's repository, and a second Mac is `git clone && dot bootstrap` with no editor in the loop. The upstream slug is now a constant in `setup-private-host` (`UPSTREAM_SLUG`); a hard fork that wants to become its own upstream should change it, and the framework never writes it into a generated flake unless the adopter declines to name a fork. The import stub means `dot adopt`'s `warn_if_unwired` is now a backstop for hand-written private repos rather than the normal path. Note the cost of `readDir`: any `.nix` file in `hosts/` becomes a host, so that directory is for host files only.

## [ADR-011] The Shell Core Is Neutral; Opinions Are Opt-In and Customisation Is Unmanaged
- **Context:** ADR-007 established that presence is not consent for destructive defaults, and `nix/home/home.nix` already gated oh-my-zsh, the Ghostty config, language servers and Node tooling behind `dotfiles.home.*`. The shell itself was never audited to the same standard, and it was imposing more than all of those combined. `programs.zoxide.options = [ "--cmd" "cd" ]` replaced the `cd` builtin for everyone. `config/zsh/modules/workshop.zsh` registered `epic-detect` as a `chpwd` hook that, on entering any directory whose `package.json` mentions `epicshop`, **wrote `.workshop.env` into that project and appended a line to its `.gitignore`** — a framework modifying repositories the user merely visited. `config/zsh/modules/utils.zsh` wrote executable `npm`, `npx` and `yarn` shims into `~/.local/bin` on first shell start, each `exec pnpm "$@"`: imperative (no rebuild or rollback could retract them), global (`~/.local/bin` is early on `PATH`, so it broke `npm` for every process, not just interactive shells), and unconditional (it ran on a cold fork where pnpm is not installed, leaving a shim that execs a missing command). `config/git/config` set `core.editor = nvim`, `merge.tool = nvimdiff`, `pull.rebase = true` and `branch.autoSetupRebase = always` globally. And there was no escape hatch at all: `.zshrc.local` was listed in `.gitignore` but nothing sourced it, so the only place to put a personal alias was a tracked framework file that the next rebuild would overwrite.
- **Decision:** Anything that changes what a standard command does, or that writes outside the user's own configuration, is opt-in; and there is always an unmanaged place to put your own.
  1. `config/zsh/custom.zsh` iterates `$DOTFILES_ZSH_MODULES` instead of a fixed source list. `nix/home/home.nix` emits that variable from the enabled toggles via `initContent = lib.mkMerge [ (lib.mkBefore "export …") … ]` — `mkBefore` rather than `home.sessionVariables`, whose ordering relative to `initContent` is not ours to depend on. The cold default is `init utils aliases exports`.
  2. New toggles, all defaulting to the existing `exampleProfile` (on only when `.local/settings.nix` sets `home.exampleProfile.enable`): `dotfiles.home.zsh.{personalAliases,nodeWorkflow,workshop}`, `dotfiles.home.zoxide.replaceCd`, `dotfiles.home.git.opinionatedDefaults`. `workshop` asserts `nodeWorkflow`, since it calls helpers the latter defines.
  3. `aliases.zsh` splits: framework entry points (`dot`, `rebuild`, `validate`, `update`, `apps`, `promote`) stay ungated; everything that redefines a system command moves to `aliases-personal.zsh`. `config/git/config` keeps identity, excludesfile, `init.defaultBranch` and colour; the workflow keys move to `config/git/config-opinionated`, included by a path that git silently ignores when Home Manager has not written it — so not writing the file *is* the off switch.
  4. The `~/.local/bin` shims are deleted outright rather than gated. A declarative system must not make imperative writes it cannot retract.
  5. `custom.zsh` sources `config/zsh/custom.local.zsh` and then `~/.zshrc.local`, last, so they win over everything above. Both are gitignored; `custom.local.zsh.example` is the tracked template. `change` now opens the escape hatch rather than a tracked file.
  6. `checks.cold-is-nondestructive` asserts the resolved cold values (`programs.zoxide.options == [ ]`, each new toggle false), so re-imposing any of this fails `nix flake check` rather than shipping green — the same mechanism ADR-007 uses for Homebrew cleanup.
- **Consequence:** A cold fork gets zsh with completion, autosuggestions, syntax highlighting, history search, fzf, zoxide as `z`, Neovim, and the `dot` CLI — and nothing that surprises. Existing users who want the old behaviour set `home.exampleProfile.enable = true` in `.local/settings.nix`, which they already have if they ran the installer. **Shims written by a previous install are not removed by upgrading**; delete them by hand (`rm -f ~/.local/bin/{npm,npx,yarn}`), because the code that created them is gone and declarative config cannot clean up an imperative write it no longer makes. `npm_config_prefix` moved from `exports.zsh` to `node.zsh` for the same reason it is gated: rewriting npm's global prefix is part of the pnpm-first workflow, not a neutral default.
